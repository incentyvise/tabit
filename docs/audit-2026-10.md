# Audit: query cache, animations/navigation, Docker (2026-10)

Status legend: ✅ fixed on this branch · ⏭ deferred (see notes)

## 1. Query cache (apps/pwa)

| # | Sev | Problem | Fix |
|---|-----|---------|-----|
| Q1 | Critical | Sign-out didn't clear the in-memory cache, the IndexedDB-persisted cache, or the offline queue → next user on the device saw the previous user's tabs/friends/balances. | ✅ `lib/session-cache.ts`: `signOutAndClear()` (cancel + clear + `persister.removeClient()` + offline queue) and `ensureCacheOwner(userId)` which wipes a cache restored for a different account. |
| Q2 | High | `api.*` wrappers swallow every error into `{success:false}`; queryFns turned that into `[]`/`null`, so failures were cached (and persisted) as successful empty data, never retried, and `isError` UIs were unreachable. | ✅ `lib/queries.ts`: all queryFns go through `unwrap()` which throws `ApiError(status)`. Retry skips 4xx. Failed queries keep their previous data and are never persisted. |
| Q3 | High | `["expenses",tabId,"all"]` was an infinite query in the prefetcher and a plain query in CSV import → import duplicate detection saw `[]`. | ✅ Distinct keys: `expenseList` (infinite), `expensesAll` (import), `expensesChart`. Import fetches fresh data with `fetchQuery` before preview. |
| Q4 | High | Tab-page prefetch key never matched the page's key (wasted request + uncached page request); synthetic `placeholderData` made `isLoading` false → "No expenses yet" flash; placeholder carried the previous tab's expenses into the next tab. | ✅ Shared `expenseListQuery()` options used by loader and page; placeholder only reused for the same tab; skeleton driven by `isPending`/placeholder state. |
| Q5 | High | `["preferences"]` cached in two shapes → wrong timezone in recurring dialog / profile. | ✅ One `preferencesQuery()` (full result); slices via `select`. |
| Q6 | High | Offline queue: transport failures dropped (never retried); SW notification actions POSTed to non-existent REST routes; no lock; no cache invalidation after replay. | ✅ Retry on transport errors only, single-flight guard, invalidation after replay; SW uses oRPC (`rpcCall`). |
| Q7 | Medium | Expense chart key (`expenses-chart`) never invalidated by any mutation/realtime event. | ✅ Key moved under `["expenses", tabId, "chart"]`, covered by prefix invalidation. |
| Q8 | Medium | Mutations missed related keys (`tabs`, `friends` list summaries, chart, detail/audit keys, settlements after member merge…); dead keys invalidated. | ✅ `invalidateTabData()` / `invalidateMembership()` used everywhere. |
| Q9 | Medium | Realtime: gaps (friends/sharedGroupTabs/recurring rule), reaction events over-invalidating, and events missed while the socket was disconnected never caught up. | ✅ Shared helpers in `invalidate-notification.ts`; reactions only touch expense keys; reconnect invalidates active queries. |
| Q10 | Medium | `gcTime` (24h) < persister `maxAge` (7d) → offline cache effectively 24h; buster = build time wiped the offline cache on every deploy; invite tokens persisted to IDB. | ✅ `gcTime = maxAge`, manual schema buster, `shouldDehydrateQuery` excludes token keys. |
| Q11 | Medium | 60s staleTime + focus refetch → ~8 requests on every app switch despite realtime. | ✅ 5 min default staleTime; realtime + reconnect catch-up keep data fresh. |
| Q12 | Low | members/manage loaders prefetched the whole ledger. | ✅ `prefetchTabMeta`. |
| Q13 | Low | Invite / add-by-QR effects re-ran non-idempotent mutations on re-render. | ✅ Run-once ref guards + stable navigate. |
| Q14 | Low | Dead `lib/query-keys.ts`, `src/lib/orpc-query.ts`. | ✅ Removed (keys live in `lib/queries.ts`). |
| — | Server | No settlement realtime notification type, so other members' settlements only appear after refetch. | ⏭ Needs a new notification type in `packages/models` + services emit. |

## 2. Animations, transitions, navigation (apps/pwa, apps/admin)

| # | Sev | Problem | Fix |
|---|-----|---------|-----|
| A1 | High | Scroll container is `main.app-main`; router never reset/restored it → detail pages open scrolled, back always lands at top. | ✅ `scrollRestoration` + `scrollToTopSelectors` + `data-scroll-restoration-id` on `<main>` (PWA and admin). |
| A2 | High | Back button used `history.go(-1)` ignoring `backHref` → dead/exit-app back button after deep link / push notification. | ✅ `canGoBack()` ? back : `navigate(backHref, {replace})`. |
| A3 | High | AlertDialog flew in from the top-left under Tailwind v4 (`translate` + keyframe `transform` stack). | ✅ Fade/zoom only, like Dialog (PWA + admin). |
| A4 | High | `useNavigate` wrapper unstable → effects re-ran every render (add-by-QR redirected away after success, double API calls). | ✅ `useCallback`-stable wrapper; run-once guards. |
| A5 | High | Same `TabPage` instance reused across `/tabs/A → /tabs/B` (filter/search/placeholder leak). | ✅ `remountDeps` on the tab route. |
| A6 | Medium | List stagger replays on every back-navigation and is uncapped on long lists. | ✅ Stagger capped to first 8 rows and only on first mount per session. |
| A7 | Medium | No reduced-motion support. | ✅ `MotionConfig reducedMotion="user"` + CSS `prefers-reduced-motion` guard. |
| A8 | Medium | Recharts animation restarted on every tab page render (unstable props). | ✅ Memoized `getMemberUser` / participants. |
| A9 | Medium | Tailwind v3 bare-var arbitrary values compile to invalid CSS in v4 (select height/origin, calendar cells, chart swatches). | ✅ v4 `(--var)` syntax. |
| A10 | Medium | Log-expense `AnimatePresence` split across ternary branches → exits never ran. | ✅ Single presence with keyed children. |
| A11 | Medium | Tab page header showed logo/no back button until the tab loaded. | ✅ Placeholder nav title set immediately. |
| A12 | Medium | 314 KB emoji picker statically imported into tab/expense route chunks. | ✅ `React.lazy`. |
| A13 | Low | `defaultPendingMs/MinMs: 0` without a pending component (no-op). | ✅ Removed. |
| A14 | Low | `useSearchParams` setter used raw `pushState(null)` (drops router history index). | ✅ Routed through router navigate. |
| A15 | Low | Slow top-nav title swap (`mode="wait"` + spring). | ✅ Short tween, `popLayout`. |
| A16 | Low | Bottom nav active state wrong for `/friends/*` subroutes. | ✅ Prefix matching. |
| A20 | Low | Theme toggle animated every `transition-*` element; toasts always dark. | ✅ `disableTransitionOnChange`, themed Sonner. |
| A19 | Low | Auth/onboarding redirects do full page reloads. | ⏭ Behaviour-preserving; move to `beforeLoad` redirects separately. |
| — | Low | View Transitions API unused. | ⏭ Optional enhancement (`defaultViewTransition`), not a bug. |

## 3. Docker / compose / nginx

| # | Sev | Problem | Fix |
|---|-----|---------|-----|
| D1 | High | `.dockerignore` only ignored root `node_modules`; sent `.turbo` (~190 MB), `.claude/worktrees`, nested `node_modules`/`dist`/`.next`, tsbuildinfo, editor dirs into every build context. | ✅ Recursive patterns. |
| D2 | High | `apps/web/Dockerfile` ran root `pnpm build` which is `--filter=!web` → web was never built; `next start` failed. | ✅ `turbo build --filter=web...`. |
| D3 | High | nginx: location-level `add_header` silently dropped all server-level security headers; un-hashed icons/splash cached 1y `immutable`; missing `/assets/*` chunks fell back to `index.html` (HTML-as-JS errors). | ✅ Headers per location, `^~ /assets/` immutable + `=404`, 1-day cache for public files. |
| D4 | Medium | No pnpm store cache → full download on every build; pnpm/turbo reinstalled per stage; turbo unpinned. | ✅ Shared `base` stage, BuildKit cache mount, turbo pinned to lockfile version. |
| D5 | Medium | Runtime images shipped all devDependencies, pnpm, curl and gnupg; ran as root; pnpm as PID 1 (poor signal handling). | ✅ `pnpm install --prod --offline` after build, doppler binary only, `tini`, `USER node`, `nginx-unprivileged`. |
| D6 | Medium | Workers always ran `doppler run` (crash without a token); migrations always via doppler. | ✅ Doppler only when `DOPPLER_TOKEN` is set; `drizzle-kit` moved to `db` deps so migrations run from prod deps. |
| D7 | Medium | `TURBO_TOKEN`/`DOPPLER_TOKEN` written as `ENV` (persisted into image config / history). | ✅ Plain `ARG`s (exposed to `RUN` only). |
| D8 | Low | Static frontends waited for API health; workers/pwa/admin had no healthchecks; unbounded json logs; api start period too short for migrations. | ✅ Compose updated. |
| D9 | Low | `tsconfig.tsbuildinfo` committed. | ✅ Untracked + gitignored. |
